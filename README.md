# Hearth 日本語版（非公式フォーク）

![Hearth — Obsidian のホーム画面](assets/Header.png)

Obsidian のホーム画面・ダッシュボードプラグイン [Hearth](https://github.com/ondreu/Hearth)（作者: ondreu）に、日本語の画面表示を追加した非公式のフォークです。
機能は本家と同じで、画面の文言だけが日本語になります。

- 元にしたバージョン: Hearth 3.6.0
- このフォークのリリース: [Releases](https://github.com/omizu555/Hearth/releases)
- Hearth の機能の詳しい説明（英語）: [本家の README](https://github.com/ondreu/Hearth#readme)、[User Guide](https://github.com/ondreu/Hearth/tree/main/docs/user-guide)

> [!NOTE]
> 本家とは無関係の非公式ビルドです。このフォークで見つけた不具合を本家に報告する場合は、まず公式版で同じ現象が起きるか確かめてください。

## 本家との違い

| 項目 | 本家（公式版） | このフォーク（日本語版） |
| --- | --- | --- |
| プラグイン ID | `hearth` | `hearth-ja` |
| プラグイン名 | Hearth | Hearth (日本語版) |
| 画面の言語 | 英語・ドイツ語・フランス語・韓国語・中国語 | 上記 ＋ **日本語** |
| 入手先 | Obsidian のコミュニティプラグイン | このリポジトリの Releases（BRAT か手動） |
| Obsidian の「更新」ボタン | 新しい公式版に更新される | **対象外**（勝手に公式版に置き換わらない） |

プラグイン ID を変えているのは、Obsidian の「プラグインの更新」で英語の公式版に上書きされないようにするためです。

## 動作条件

- Obsidian 1.8.7 以降（デスクトップ・モバイルどちらも可）
- Obsidian の表示言語が **日本語** であること
  （設定 → Obsidianについて → 言語 で「日本語」を選び、Obsidian を再起動。英語表示のときは Settings → General → Language）

Hearth は Obsidian の表示言語に合わせて画面の言語を切り替えます。Hearth 側に言語の設定はありません。

## インストール（BRAT を使う方法・おすすめ）

[BRAT](https://github.com/TfTHacker/obsidian42-brat) は、コミュニティプラグインに登録されていないプラグインを GitHub から入れるためのプラグインです。

1. **BRAT を入れる**
   設定 → コミュニティプラグイン → 「閲覧」で「BRAT」を検索してインストールし、有効にします。
   （コミュニティプラグインを初めて使う場合は、先に「制限モード」をオフにします）
2. **Hearth 日本語版を追加する**
   コマンドパレット（`Ctrl+P` / `Cmd+P`）で次のコマンドを実行します。
   ```
   BRAT: Plugins: Add a beta plugin for testing (with or without version)
   ```
   BRAT の設定画面の「Beta プラグインを追加」ボタンからでも同じ画面が開きます。
3. **リポジトリとバージョンを指定する**
   - 「リポジトリ」欄に `omizu555/Hearth` を入力します。
   - 「バージョンを選択」で **`3.6.0-ja.1` のような具体的なバージョン** を選びます。
     「最新バージョン」を選ぶと、BRAT が起動のたびに自動で更新します（[自動更新について](#自動更新について勝手にバージョンを上げない)）。
   - 「インストール後にプラグインを有効化」にチェックを入れます。
4. 「プラグインを追加」を押します。
5. 設定 → コミュニティプラグイン に「Hearth (日本語版)」が表示され、有効になっていれば完了です。

BRAT の画面は、Obsidian が日本語なら日本語で表示されます（コマンド名だけは英語です）。

## インストール（手動で置く方法）

BRAT を使えない環境向けです。

1. [Releases](https://github.com/omizu555/Hearth/releases) から使うバージョンを開き、次の3ファイルをダウンロードします。
   - `main.js`
   - `manifest.json`
   - `styles.css`
2. 保管庫のフォルダの中に `.obsidian/plugins/hearth-ja/` フォルダを作り、3ファイルを入れます。
   ```
   <保管庫>/
   └─ .obsidian/
      └─ plugins/
         └─ hearth-ja/
            ├─ main.js
            ├─ manifest.json
            └─ styles.css
   ```
   `.obsidian` は隠しフォルダです。Windows のエクスプローラーでは「表示 → 隠しファイル」をオンにすると見えます。
3. Obsidian を再起動し、設定 → コミュニティプラグイン で「Hearth (日本語版)」を有効にします。

手動で置いた場合、ファイルを置き換えない限りバージョンは変わりません。

## 自動更新について（勝手にバージョンを上げない）

Hearth 日本語版のバージョンが勝手に上がる可能性があるのは、BRAT の自動更新だけです。

| 仕組み | 勝手に更新するか | 対策 |
| --- | --- | --- |
| Obsidian の「プラグインの更新」 | しない。公式ストアに登録されたプラグインだけが対象で、`hearth-ja` は対象外 | 不要 |
| Obsidian の「プラグインの更新を自動で確認」 | しない。オンにしても通知が出るだけで、インストールはしない（既定はオフ） | 不要 |
| BRAT の「起動時に Beta プラグインを自動更新」 | **する**（既定でオン）。「最新バージョン」で追加したプラグインは、新しいリリースが出ると起動時に更新される | 下のどちらか |
| Hearth 本体 | しない。自分自身を更新する機能はない | 不要 |

BRAT で勝手に更新させない方法は2つあります。どちらか一方で十分です。

- **バージョンを固定して追加する（おすすめ）**
  追加するときに「最新バージョン」ではなく具体的なバージョン（例: `3.6.0-ja.1`）を選びます。固定したプラグインは、BRAT の起動時の自動更新から外れます。
  BRAT の設定画面のプラグイン一覧に「追跡中のバージョン：3.6.0-ja.1（固定）」と表示されていれば固定されています。
  すでに「最新バージョン」で追加した場合は、一覧の編集ボタンからバージョンを選び直すと固定できます。
- **BRAT の自動更新をオフにする**
  設定 → BRAT → 「起動時に Beta プラグインを自動更新」をオフにします。BRAT で入れたすべてのプラグインが自動更新されなくなります。

## 新しいバージョンに上げたいとき

このフォークで新しいリリース（例: `3.6.0-ja.2`）が出たら、自分のタイミングで上げます。

- **BRAT で入れた場合**: 設定 → BRAT のプラグイン一覧で `omizu555/Hearth` の編集ボタンを押し、新しいバージョンを選んで「バージョンを変更」を押します。
- **手動で置いた場合**: 新しいリリースの3ファイルで `.obsidian/plugins/hearth-ja/` の中身を置き換え、Obsidian を再起動します。

どちらの場合も、ダッシュボードや設定（`.obsidian/plugins/hearth-ja/data.json`）はそのまま残ります。

## 公式版の Hearth から乗り換える

公式版（`hearth`）と日本語版（`hearth-ja`）は、**同じ保管庫で同時に有効にしないでください**。同じ画面（ホーム画面など）を登録するため、ぶつかって正しく動きません。

公式版で作ったダッシュボードや設定を引き継ぐ手順:

1. 設定 → コミュニティプラグイン で公式版の「Hearth」を無効にします。
2. 日本語版を[インストール](#インストールbrat-を使う方法おすすめ)します（まだ有効にしない）。
3. `.obsidian/plugins/hearth/data.json` を `.obsidian/plugins/hearth-ja/data.json` にコピーします。
   中身は同じ形式なので、そのまま使えます。
4. 日本語版の「Hearth (日本語版)」を有効にします。
5. 問題がなければ、公式版の「Hearth」をアンインストールします。

## はじめての使い方

1. 初めて有効にすると、初回セットアップウィザードが開きます。目的や使いたいカードを選ぶと、ダッシュボードが作られます（公式版から設定を引き継いだ場合は開きません）。
   あとからやり直すときは、コマンドパレットで「Hearth: Hearthをセットアップ（初回セットアップウィザード）」を実行します。
2. ホーム画面は、左のリボンの「Hearthのホームを開く」アイコンか、コマンド「Hearth: ホームダッシュボードを開く」で開きます。
3. ダッシュボード右上の配置ボタン（マウスを乗せると「カードの移動・サイズ変更」と表示）を押すと、カードの追加・移動・サイズ変更・設定ができます。終わったら「配置を完了」を押します。
4. 全体の設定は 設定 → Hearth です。タブは「外観」「検索」「ダッシュボード」「挙動」「モバイル」「連携」「バックアップ」「情報」に分かれています。
   - 起動時にホーム画面を開くか: 「挙動」→「起動時に開く」
   - 空の新規タブの代わりにホーム画面を出すか: 「挙動」→「新規タブを置き換える」

カードの種類や各機能の詳しい説明は、[本家の README](https://github.com/ondreu/Hearth#readme)（英語）を見てください。

## 日本語にならないとき

- **Obsidian の表示言語を確認する**: 設定 → Obsidianについて → 言語（英語表示では Settings → General → Language）が「日本語」になっているか確認し、変えたら Obsidian を再起動します。
- **日本語版を使っているか確認する**: 設定 → コミュニティプラグイン に「Hearth (日本語版)」があり、有効になっているか確認します。公式版の「Hearth」には日本語が入っていません。
- **再読み込みする**: 「Hearth (日本語版)」を一度無効にしてから有効にするか、Obsidian を再起動します。

## 英語のまま残しているもの

次のものは、意図して英語のままにしています。

- **製品名・プラグイン名**: Hearth、Obsidian、Dataview、Excalidraw、Templater、Jira、Git など
- **検索バーの入力例とインスタント回答**: 計算・通貨換算・天気・日付などの「インスタント回答」は、本家と同じく英語の入力だけを解釈します（例: `20% of 150`、`10 km to mi`、`weather Tokyo`）。
- **天気の地名検索**: 地名はローマ字で入力してください（例: `Tokyo`、`Osaka`）。結果は日本語名で表示されます。
- **クリップカードのフィルター構文**: `lower`、`truncate:80` など、コードが読み取る書式
- **「新機能」ダイアログの更新履歴**: 本家の CHANGELOG の内容（英語）をそのまま表示します。
- **最初に作られるダッシュボード名・カード名などの初期値**: 保管庫に保存されるデータなので英語の初期値のままです。あとから自由に変更できます。

## メンテナンス（このフォークを更新する人向け）

### ブランチの構成

| ブランチ | 内容 |
| --- | --- |
| `main` | 本家のミラー（README だけ本家へのリンクに置き換え） |
| `ja` | 日本語版。本家のリリースタグを元に、日本語の追加とプラグイン ID の変更を載せたもの |

日本語版に関係する変更は次のファイルだけです。

- `src/locales/ja.ts` — 日本語の訳文（`en.ts` と同じ構成）
- `src/locales/index.ts` — 言語の一覧に `ja` を登録
- `manifest.json` / `manifest-beta.json` — プラグイン ID・名前・説明・バージョン
- `README.md` — この文書

### ビルド

```sh
npm ci
npm run build   # 型チェック（ja.ts の抜け・余分なキーも検出）＋ main.js の生成
```

`npm test` は、Windows では日付・時刻の書式の違いで天気まわりのテストが7件失敗します。本家 3.6.0 でも同じなので、日本語化とは関係ありません。

### 訳を直してリリースする

1. `src/locales/ja.ts` を直します。
2. `manifest-beta.json` の `version` を上げます（例: `3.6.0-ja.1` → `3.6.0-ja.2`）。`manifest.json` の `version` は本家のバージョン（`3.6.0`）のままにします。
3. `npm run build` が通ることを確認します。
4. コミットしてタグを打ち、push します。
   ```sh
   git commit -am "fix(i18n): ..."
   git tag -a 3.6.0-ja.2 -m "Hearth 3.6.0 日本語版"
   git push origin ja 3.6.0-ja.2
   ```
5. リリースを作ります。BRAT はリリースに添付された `manifest.json` のバージョンとタグが一致することを求めるので、`manifest-beta.json` を `manifest.json` という名前で添付します。
   ```sh
   mkdir -p /tmp/release && cp main.js styles.css /tmp/release/ && cp manifest-beta.json /tmp/release/manifest.json
   gh release create 3.6.0-ja.2 --verify-tag --title 3.6.0-ja.2 --notes "..." \
     /tmp/release/main.js /tmp/release/manifest.json /tmp/release/styles.css
   ```

このフォークでは GitHub Actions を有効にしていないため、本家の自動リリース（`.github/workflows/release.yml`）は動きません。Actions タブで有効にすれば、手順 4 のタグの push だけで手順 5 と同じリリースが作られます。

### 本家の新しいバージョンに追従する

1. 本家のタグを取り込み、`ja` ブランチにマージします。
   ```sh
   git fetch upstream tag 3.7.0 --no-tags
   git switch ja
   git merge 3.7.0
   ```
2. `npm run build` の型チェックが、`ja.ts` に足りないキー（本家で増えた文言）を一覧で出します。`en.ts` を見ながら訳を足します。
3. `manifest.json` を本家の新しい内容に合わせつつ、`id`・`name`・`description` を日本語版のものに戻します。`manifest-beta.json` の `version` は `3.7.0-ja.1` にします。
4. 上の「訳を直してリリースする」の手順 3〜5 でリリースします。
